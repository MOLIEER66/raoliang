# PRD · 绕梁 v0.1 → v1.0

## 0. 这份文档回答什么

不做功能堆砌。先回答三个内核问题：给谁、图什么、凭什么。功能是从这里推出来的，不是拍脑袋列的。

## 1. 定位（内核结论）

表面需求：一款适配安卓 16 的音乐 APP。
内核真相：这是一个**校招面试作品**，附带真实用户（QQ 群）。

因此有**双交付物**，一份代码两个观众：

1. 给群友：一个能装、好用、持续更新的 APK（GitHub Release 页下载）
2. 给面试官：一个开源仓库，能支撑 30 分钟不塌的技术对话

取舍冲突时优先保证 2)——群友只需要"能用"，面试官决定你拿不拿 offer。

## 2. 用户与场景

- **用户 A（群友）**：装上 → 导入音源 → 听歌。容忍度高，崩了进群骂一句。
- **用户 B（面试官）**：打开仓库 90 秒内看懂项目是什么、工程是否规范。

## 3. 北极星指标

- 对 A：从装上到听到第一首歌 ≤ 4 步（导入音源算一步）
- 对 B：仓库里"被追问后不塌"的决策数（ADR / 架构图 / 适配说明）≥ 8

## 4. 范围

### P0（没有就不配叫音乐播放器）

1. 本地音乐扫描与播放（保底能力，不依赖任何服务器）

4. 歌词逐行滚动
5. 洛雪音源脚本导入 + 多音源切换
6. 歌单：新建 / 添加 / 重命名 / 删除

### P1（好用）

### P2（质量优先，全做）

### 非目标（写下来才不会烂尾）

## 5. 搜索方案：已验证走服务端，架构上留后路

背景：洛雪音源脚本只提供"播放地址 / 歌词 / 封面"，不含搜索。

- **主路线（已实测可用）**：调用音源服务端的聚合搜索接口，APP 内直接搜
- **兜底（必做）**：洛雪歌单 JSON 导入、本地文件、系统"分享到APP"接收歌名——服务端挂了搜索消失，但 APP 仍是完整播放器
- **不做**：APP 内置多平台聚合搜索——维护地狱，反爬一变就全崩，收益配不上代价

### 5.1 实测记录（2026-09-05）

- 端点：`GET /api/music/search`（SERVER_ADDRESS_REDACTED）
- 参数：`keyword`（`q` 亦可）、`source`、`key`；仅支持 GET，UA 无要求
- 实测 `keyword=晴天` → code 200，total 114，聚合模式 `platform=all / mode=lx`，字段含 songId / name / singer / album / duration / platform，首条即周杰伦《晴天》
- 风险注记：该服务器为第三方公益服务（其他端点实测出现过 429 限速、401 鉴权），按"随时可能挂"设计：失败降级提示 + 兜底导入 + 多音源冗余

## 6. 音源策略（法律与简历双安全线）

- 应用本体零曲库、零内置服务器地址
- 兼容洛雪脚本协议（musicUrl / lyric / pic），脚本由用户自己导入
- 脚本在应用内受限环境执行（详见 [ADR-0002](ADR-0002-source-plugin.md)）
- 失效降级：多源冗余、单源失败自动切换、错误可读提示

## 7. Android 16 适配清单（面试谈资库）

- targetSdk 36
- Edge-to-edge 全面屏内容延伸（15+ 强制）
- 前台服务类型 `mediaPlayback` 合规声明（否则后台播放被系统杀）
- 预测性返回手势（Predictive Back）
- 通知权限（13+ `POST_NOTIFICATIONS`）与媒体通知样式
- 本地音频读取权限（13+ `READ_MEDIA_AUDIO` 细分权限）
- 16KB 内存页（若引入原生库需验证）
- 自适应图标 / 主题图标

## 10. 原创性红线（2026-09-05 新增，硬性）

1. **不模仿**：网易云、QQ音乐、Spotify、Apple Music 是"避雷清单"而非参考——不复刻它们的界面结构、交互流程、配色心智；每个屏幕都要能回答"主流产品这里是怎么做的，我们为什么不同"
2. **去AI味**：禁止表情符号当图标、万能紫蓝渐变、玻璃拟态堆砌、无信息密度的均匀卡片矩阵；每个视觉决定必须能在设计系统里找到依据，找不到依据的就删
3. **品牌原创**：名称、图标、配色、字体策略必须原创，名称须检索确认无重大撞名
4. **面试防线**：这个项目的每一笔都要能被你亲口讲出"为什么"；讲不出的设计等于没设计
